# Products Only
Small iOS app experimenting with the DummyJSON Products API

Building a demo app today is a completely different experience compared to two years ago. Having AI as a development partner allows us to focus on far more aspects of the application and deliver a much more detailed, polished solution in the same amount of time.
With that in mind, this application was built by leveraging AI tooling—with **Claude Code** serving as the primary development partner.

## Tech Stack

* **Language & Concurrency:** Swift 6, `async/await`
* **Architecture & Modularity:** Clean Architecture, Multi-module project, Swift Package Manager (SPM), Dependency Injection
* **UI & State Management:** SwiftUI, The Composable Architecture (TCA), SwiftUI `NavigationStack` backed by TCA stack state
* **Testing:** Swift Testing

## Main Decisions

To keep the implementation structured and manageable, the development process was broken down into clear, incremental stages:

1. Setting up the Git repository along with minimal baseline documentation for Claude to use as context during development.
2. Defining the initial project skeleton.
3. Implementing a minimal REST client, just enough to supply the app with the required data.
4. Using **Claude Design** to craft a set of Design System components.
5. Defining a `StyleGuide` module containing reusable colors, images, spacing tokens, etc.
   * Exported the assets from the Design System created in Claude Design and imported them into the project.
6. Adding support for localized strings.
7. Implementing reusable UI components as part of the `DesignSystem` module.
   * Imported these elements from the Design System created via Claude Design.
8. Implementing the **Products List** screen.
9. Implementing the **Product Details** screen.
10. Defining a `Tracking` module with a minimal set of features to demonstrate the proposed analytics approach.

## What's Next

* **Snapshot Testing:** Snapshot tests have not been added yet and are one of the next priorities. Point-Free's [`swift-snapshot-testing`](https://github.com/pointfreeco/swift-snapshot-testing) would be the library of choice for this.
* **Adaptive Layouts (iPhone Duo & iPad):** The current UI layout works on the new iPhone Duo, though it is not specifically optimized for it. Proper size classes and a dedicated layout that takes full advantage of the extra screen real estate on iPhone Duo and iPads should be implemented.
* **API Payload Optimization:** On the Products List screen, even though only the displayed fields are decoded, the API still returns all unused fields in the payload. This can be optimized by using the `select` query parameter.

## Tracking

To demonstrate how we can validate whether the solution delivers value for merchants, a `Tracking` module was implemented. It provides a minimal suite of tracked events and user interactions, showcasing the proposed analytics pattern across both the **Products List** and **Product Details** screens.

## Use of AI

AI was used consistently at every stage of building this solution. **Claude Code**—alongside its design capabilities (**Claude Design**)—was the primary tool used for implementation, while **Codex** was used for code reviews.

Thanks to a clear breakdown of development stages and small, well-scoped units of work, we avoided unexpected context or merge conflicts.

When integrating UI components into the `DesignSystem` module, Claude occasionally overcomplicated view implementations—as expected. For example, for `GalleryView`, it initially generated an unperformant solution that stacked images one on top of another inside a stack view. Similarly, for the Products List screen, Claude's proposed implementation was functional, but relied on an excessive number of helper properties without any real justification.

At every step of the process, manual intervention was applied to review, refactor, and simplify the code generated by Claude.
